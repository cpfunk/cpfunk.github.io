Creating a RISC-V Microprocessor for Micro Quadcopter Applications

Project Overview

For my senior design project, a team of other EE and CprE seniors and I are creating a microcontroller (MCU) that features interfaces and features targeting high-performance micro quadcopter applications like the Crazyflie 2.1.

The MCU we are creating features support for protocols such as SPI, I2C, UART. It also features PWM support for controlling the quadcopter's motors, PID acceleration for controlling the PWM outputs, and a Trigonometric Unit (TMU). This TMU enables the efficient processing of positional data from the Inertial Measurement Unit (IMU). We plan to have this microcontroller fabricated in the spring using the Sky130 open-source process.

My Role

My role in this project involves designing and testing various pieces of hardware on the microcontroller, such as the I2C interface. I am also the team's documentation lead, so I am responsible for creating and maintaining this project's documentation.

Skills or Knowledge Gained

Through this project, I am learning how to perform randomized unit testing using SystemVerilog. I am also learning the process of verifying a digital chip such that we can be confident that it will work once it is fabricated. This verification process involves running both gate-level and FPGA simulations.

Resources Used

  • All of the members on the team have experiencing designing a RISC-V processor, however, to speed up development time and enable a more focused approach to engineering and creating the core features that set this microcontroller apart, we chose to use a pre-tested open-source 32-bit RISC-V processor IP.
  • In creating this project, our team used ChipFoundry's CLI to synthesize the Verilog HDL, run simulations, and perform place and route.
  • We also referenced "The CORDIC Trigonometric Computing Technique" by Jack E. Volder when designing our CORDIC-based TMU.
  • When designing the I2C interface, we used the "I2C-Bus Specification and User Manual" by NXP Semiconductors as a reference.
  • When designing the SPI interface, we referenced "SPI Interface Specification" by VTI Technologies.
  • When designing the UART interface, we referred to "UART: A Hardware Communication Protocol Understanding Universal Asynchronous Receiver/Transmitter" by Peňa and Legaspi, published in AnalogDialogue.
